# PR #508: Cache evaluation results for 60 seconds

**kofi-mensah** wants to merge 2 commits into `main` from `kofi/eval-cache` · relates to FLAG-287

## Description

A profile of the Black Friday load test shows `evaluate()` is about 35% of our CPU: a product page evaluates ~40 flags for the same user and each one walks the rules. This **caches the answer per (flag, user) for 60 seconds**.

**Update (commit 2, "Address review"):**

- the cache is **cleared whenever a node applies an update** (`applyUpdate` / `loadSnapshot`), so a kill switch is visible immediately
- the key is now `JSON.stringify([key, user.id])`, so `("a", "bc")` and `("ab", "c")` no longer collide
- the cache lives in the `store` (one per app, not module-level) and is capped at 100,000 entries; the oldest entry is dropped first
- TTL uses the injected `now()` instead of `Date.now()`
- put the "off again" assertion back, and added tests for the clear on update and the cap
