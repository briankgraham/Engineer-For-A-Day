# PR #508: Cache evaluation results for 60 seconds

**kofi-mensah** wants to merge 1 commit into `main` from `kofi/eval-cache` · relates to FLAG-287

## Description

A profile of the Black Friday load test shows `evaluate()` is about 35% of our CPU: a product page evaluates ~40 flags for the same user and each one walks the rules. Flags barely change and users keep asking about the same flags, so this **caches the answer per (flag, user) for 60 seconds**.

- `evaluate()` checks a `results` Map first and only computes on a miss
- entries expire after 60 s
- the SDK already caches for 5 minutes, so 60 s on the server is well inside what clients see anyway
- one existing test asserted the flag turns off straight after `setEnabled(false)`. That is not true any more within the TTL, so I dropped that assertion

Would love to land this before Friday's load test 🙏
