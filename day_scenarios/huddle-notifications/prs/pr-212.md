# PR #212: Rate limiter: in-memory token bucket instead of Redis

**lena-fischer** wants to merge 1 commit into `main` from `lena/ratelimit-memory` · relates to PING-198

## Description

Rate-limit checks are ~40% of our Redis ops (one sorted-set read and write per push). This replaces the rolling window with a **token bucket per user, kept in process memory**, so a check is just a Map lookup.

- 5 tokens per user, a full refill every hour (same "5 per hour" limit as before)
- no Redis round trip on the hot path
- skipped two rate-limit tests that are flaky with the new limiter (they lean on the fake clock); I'll fix them in a follow-up
