## Format
- [x] Persona-initiated follow-ups (2026-10-03): timeline events can be `"type": "followup"` (the coworker's message is written live from a stage direction in `secret.json` `followups`, with `text` as the fallback) and `"delay"` (sim minutes after the `when` trigger). New triggers are `pr_approved:<id>` and `pr_feedback:<id>` (request changes or comment). A PR can have `revisions`, which a `"revise"` pushes. Seeded issues can carry `"rev"`. In shipfast, Marco pushes v2 of PR #87 30 minutes after you request changes. v2 fixes the declines, `log` and the off-by-one, but adds a new key per attempt and a test that can't fail. It comes with a "Re-review" task and the `key-per-attempt` flaw. Approving gets a "merging" DM instead. Huddle (Lena, PR #212) has no follow-up yet.
- [ ] Dana posts the status page from your updates, so the quality of the updates is visible. Could be a `followup` in the incident channel after `posted:incident`.
- [ ] Let the candidate open their own PR for the incident fix and get it reviewed by Priya (a reviewer persona with planted nitpicks).
- [x] Day history (2026-10-03): "Past days" on the list page (`day-history-v1` in localStorage, newest first, max 50); reviewed entries expand to the full manager review; "Abandon" adds an "Abandoned" row (no review, shows how far you got). Every row has Delete, and "Clear history" empties the list. "Start over" on a reviewed day keeps its review in history; reviews finished before this were backfilled once.
- [x] "Start with AI" (2026-10-04): each day card offers "Start" or "✦ Start with AI"; the mode is fixed for the attempt (`sess.ai`). It has no persona and no planted flaws. Its code blocks get Apply. The transcript goes to the evaluator, which adds `DAY_EVAL_AI`; the review and Past days show a "with AI" tag.
